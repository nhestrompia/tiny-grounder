# Agent benchmark v2: power calculation

Plan v2.1 step 7: *run a quick power calculation before freezing the task count*. Generated by `tools/bench_v2_power.py` from the v1 logs (`runs/cli*/logs`); re-run it after the first full sweep to replace the planning scenarios with the measured v2 variance.

## Model

For two arms A, B and one agent, with R repeats per task and arm: `d_t = mean_r(A) - mean_r(B)`,
`Var(d_t) = sigma_b^2 + sigma_w^2 / R`. sigma_b^2 is the between-task variance of the *true* difference (repeats cannot reduce it); sigma_w^2 is run noise, `E[p_A(1-p_A) + p_B(1-p_B)]` (shrinks with R). Tasks of one site are correlated, so N tasks on S sites carry the design effect `DE = 1 + (N/S - 1) rho`; planning values here: N = 66, S = 19 sites (m = 3.5 tasks per site), rho = 0.25 (judgement; v1 estimates where the difference varies by task: 0.33, 0.33, 0.00, 1.00).
CI half-width = `1.96 sqrt(DE Var(d_t) / N)`. Non-inferiority at margin M: one-sided 95% test, 80% power, true difference 0: `N = DE Var(d_t) ((1.645 + 0.842) / M)^2`.

## Recommendation

**Freeze 66 tasks (about 19 sites) and run 3 repeats per arm; extend only the two `find` arms when the first sweep says so.**

* CI half-width <= 5 points for a paired difference needs 48 tasks at R = 3 if the v2 tasks behave like v1 (ceiling effects), but 220 (blend vs exact) and 307 (find vs page view) at R = 3 once success is around 75%: with 66 tasks the half-width is 4.2 / 9.1 / 10.8 points in the three scenarios. Repeats only attack sigma_w^2; sigma_b^2 (tasks on which the arms truly differ) needs more tasks, not more runs.
* The 2-point non-inferiority test for blend vs exact needs 480 tasks at R = 3 even in the v1-like scenario and 905 at R = 8 with harder tasks. **66 tasks cannot demonstrate non-inferiority at 2 points** unless the two rankers produce near-identical runs (sigma_w^2 and sigma_b^2 close to 0, as in v1 for the Sonnet and GPT-6.2 find arms). Pre-register the reading: the gate passes only if the paired CI lower bound is above -2 points; otherwise report 'not shown non-inferior' and the CI, and do not read a wide CI as equivalence.
* The 5-point margin against the best baseline needs 494 tasks at R = 3 in the harder scenario if the true difference is 0. With 66 tasks the test has 80% power only if `find` is truly better than the baseline by about +9 points (R = 3) / +5 points (R = 8); in the v1-like scenario +0 points. The same holds for the 2-point blend-vs-exact test: it would need the blend to be truly better by +10 points (R = 3, harder tasks) / +3 points (v1-like). Read a failed gate as 'not shown', never as 'worse'.
* Because the harness resumes (a run whose record exists is skipped), the cheap extension is: run all arms at R = 3, compute the paired report, and if the blend-vs-exact half-width exceeds 5 points re-run only `find@exact` and `find@blend` with `--repeats 8` (about 2 x 66 x 5 = 660 extra runs per agent).
